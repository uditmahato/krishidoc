# UI Designer Review (Module 12 pre-review)

VERDICT: there is no design system, only 7 colour constants, 4 spacing numbers, and a 3-line theme that seeds a Material palette and THROWS THE AUDITED TOKENS AWAY.

## THE HEADLINE DEFECT
`theme.dart:7` uses `ColorScheme.fromSeed(seedColor: KdColors.primary)`. Seeding #1B5E20 produces **#286C2A**, not #1B5E20. So the colour shipping on every icon, button and app bar was NEVER the colour anyone contrast-checked: 6.42:1 actual vs the 7.87:1 the token file believes. KdColors.primary is a HINT, never a rendered value. Fix: stop seeding, declare an explicit ColorScheme (full spec in the agent output).

## Also measured wrong
tokens.dart comments are decorative and four are incorrect: #1B5E20 claimed 8.6:1 is actually **7.87** (overstated, the direction that matters); #9A5B00 claimed 4.8 is 5.43; #B91C1C claimed 5.9 is 6.47; #44483F claimed 8.4 on white is 9.36 (8.45 happens to be its ratio against M3 surfaceContainerLow, suggesting the numbers were measured against inconsistent backgrounds then labelled "on white"). The agent verified its calculator against the four canonical WCAG reference pairs first. FIX: correct them + a ~60-line contrast_test.dart making the palette permanently falsifiable, the same discipline the sealed DiagnosisPresentation already applies to result states.

## Gaps (ranked)
1. **Audited tokens never reach the screen** (above). S / High.
2. **Cards are INVISIBLE: 1.05:1 against the canvas.** No cardTheme, so M3 defaults give #F3F4EE on a #F9FAF3 scaffold, delineated by nothing but a 1dp shadow, which is the first thing to disappear on a 720p LCD in field sunlight. Also Card's default EdgeInsets.all(4) stacks on the 8dp separator so history's real gap is 16dp while the code reads 8. FIX: white fill, zero margin, radius 16, 1dp #868E7E border (load-bearing: satisfies 1.4.11 on both sides and survives sunlight where the shadow does not), plus a KdElevation token set of real BoxShadows. S / High.
3. **No type scale, and Devanagari is rendered with English metrics.** Flutter's M3 Typography.tall2021 is BYTE-IDENTICAL to englishLike2021 (the SDK comment says M3 "does not include tall text themes"). So titleLarge ships 22sp at height 1.27 = 27.9px, where stacked matras and conjuncts collide between lines, and bodyLarge ships letterSpacing 0.5, which breaks the shirorekha, the connected line Devanagari reads along. No font is bundled, so metrics vary by OEM ROM and any line-height spec is unenforceable. ne/hi also run longer: shutterLabel 10->17 chars (1.7x). FIX: 9-step KdType with a locale-aware Devanagari column (line-height floor 1.45 at >=19sp, letterSpacing 0 without exception, leadingDistribution even), bundle Noto Sans Devanagari subset (~180-260KB against a 60MB budget). M / High.
4. **No dark theme, no sunlight theme** despite bright sun being the named primary environment. MaterialApp.highContrastTheme activates automatically from the OS flag and is unused. FIX: kdDarkTheme (elevation as surface steps, never shadow) + kdSunlightTheme (21:1 text, 2dp borders, no shadows, weights bumped) wired to highContrastTheme AND a manual toggle. M / High.
5. **Seven constants, no ramps, no roles.** Every component inventing its own: capture_screen.dart:202 computes `(isReady ? primary : textPrimary).withValues(alpha: 0.85)`, a colour in no token file whose contrast depends on the camera frame underneath it. FIX: four ramps + slate + a semantic role layer; the three state* triplets are what make the diagnosis cards distinguishable WITHOUT READING. M / High.
6. Contrast comments wrong + untested (above). S / Med.
7. **Three unrelated corner languages on one screen:** Card 12, Chip 8, buttons StadiumBorder (a 24dp pill). Fully-round pills read as generic Google and sit badly next to rectangular photographic content. FIX: KdRadius sm8/md12/lg16/xl24/full; replace StadiumBorder everywhere. S / Med.
8. **Spacing scale too coarse:** nothing between 8 and 16 (where separators, badge padding and icon-label gaps live), nothing above 24, and minTouchTarget is being used as a LAYOUT HEIGHT at capture_screen.dart:243. Page gutter and card padding are both `md`, so card content sits 32dp from the edge while the tagline sits at 16dp: nothing in the app shares a left edge. FIX: 11-step scale + KdLayout semantic constants; screens use KdLayout, components use KdSpacing, nothing outside the DS uses a raw number. S / Med.
9. **Buttons: no hierarchy, no states, no destructive variant.** theme.dart sets ONE property on TWO types. `Size.fromHeight(48)` constrains height only, min width falls to 0: it reads like a touch-target guarantee and is not one. TextButton gets no theme at all, so the two debug buttons are 40dp, UNDER the Android minimum. The disabled shutter renders as M3's 12%-opacity ghost, indistinguishable from "broken" for a user who cannot read the coaching. FIX: five roles; disabled must stay READABLE (#5A6353 on #E4E7DC = 5.01:1) because for this audience disabled must read as "not yet", never "broken". M / High.
10. **Iconography mixes weights within one row** (three outlined + one filled), uses two glyphs for the same action across screens (photo_camera_outlined vs photo_camera; check_circle_outline vs check_circle), hardcodes `size: 32` so at Large font the label grows 30% and the icon does not (inverting the ratio for exactly the users who depend on the icon most), and picks metaphors that will not land: a CALL-CENTRE HEADSET for "ask a nearby crop expert" who is a person standing in a field, a SPA FLOWER for "crop", a BROKEN-ASSET glyph for "we could not identify this plant". For a low-literacy user the icon IS the label. FIX: single outlined family, scaling size token, five commissioned pictograms, and where an icon carries state always pair glyph AND colour, never colour alone. M / Med.
11. **Home grid: no priority, and it clips.** "Identify disease" has identical size/colour/radius/elevation/icon treatment to "Settings". childAspectRatio derives height from WIDTH, so tile height is independent of content and textScaler: at 360dp the tile is 130dp fixed, but Android's Large setting needs ~166dp. It overflows and clips, and Nepali reaches three lines sooner. The comment at :34 says the screen scrolls "so large font scales never clip content": true of the PAGE, false of the TILE, because the overflow is inside a box the scroll view cannot grow. FIX: two-tier layout, KdHeroActionCard (176dp, the only element above the fold) + 3-up KdQuietTiles using mainAxisExtent, + a KdContextPill showing the remembered crop, which Home never mentions today despite D-16 making it core state. M / High.
12. **The diagnosis cards are three identical white rectangles.** State is encoded ONLY in words, in a language many users read slowly, at arm's length in sunlight. The certainty Chip never sets labelStyle so it inherits onSurfaceVariant and passes 7.21:1 BY ACCIDENT, chosen by nobody, tested by nothing. Alignment is inconsistent inside one family (confident uses .start, the others .stretch). Alternatives are dead 4dp-padded text with no touch target, no likelihood, and no hanging indent so wrapped Devanagari runs under the bullet. No photo anchors the result to the leaf. escalateToClinic expands 1.42x into Nepali inside a fixed-height button. FIX: KdStateCard with a 6dp tone rail, tone-50 header band, thumbnail, and KdCertaintyBadge with owned ratios (9.32 / 9.48 / 11.19). M / High.
13. **Empty, error and loading are bare centred sentences.** Empty History is the SECOND screen a new user reaches and is where the app should hand them the camera; instead it is a dead sentence. The error branch has NO retry, teaching learned helplessness. Camera failure INSTRUCTS the user to open phone settings while openAppSettings() is one call away: the clearest instance of the app describing an action rather than offering it. FIX: one KdEmptyState component, four instances; History empty becomes the funnel. S / Med->High.

Actions: KdPrimaryButton/KdSecondary/KdDestructive/KdDestructiveQuiet/KdTextButton v1, KdShutterButton v1 (72dp circle: every camera app on earth uses a centre circle and that muscle memory is universal), KdContextPill v1.
Feedback: KdCertaintyBadge v1, KdCoachBanner v1 (OPAQUE), KdEmptyState/KdErrorState/KdSkeletonRow v1, KdConfirmSheet v1.
Illustration set v1: five 120dp two-tone illustrations + five 24dp pictograms. One designer week; the highest craft-per-rupee line item, because it is what separates "a Flutter app" from "a product" for a user who navigates by picture.
