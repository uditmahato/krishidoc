## Measured on device (Realme RMX3741, Android 15, arm64, debug build)

First real-hardware run, 2026-07-27. Debug Dart is unoptimised, so timings are pessimistic bounds; release is materially faster. Figures below reproduced across two independent runs.

**Release install verified 2026-07-27.** V1 (`com.example.krishidoc`) was removed by the owner and the V2 **release** build installed as `com.krishidoc.app` (arm64-only APK, 20.9 MB; the `--split-per-abi` arm64 artifact is 17.9 MB). It launched, created its surface at 1080x2412, and logged no errors, exceptions, or Dart failures. Because `main()` awaits `AppServices.open()` before `runApp`, a rendered UI is proof that the real SQLite database opens successfully on device in release mode, not just under the test harness. The log also shows the render context being destroyed about nine seconds after launch when the app lost its surface, which independently corroborates the screen-sleep explanation for the integration-run failures below.

**Device-run procedure and its caveat:** run `flutter test integration_test/device_verification_test.dart -d <serial>`. The phone must stay awake and unlocked for the whole run: two later attempts died at roughly the 15 second mark with every test reported as "did not complete" and the VM connection dropped, which matches ColorOS suspending a backgrounded app rather than any defect in the code (the same suite had already passed four of five tests twice, and the entire local suite stays green). Waking the screen would need `adb shell input`, which the phone-automation boundary forbids, so this stays a manual precondition.

- **Release APK per ABI: 15.4 MB (armeabi-v7a), 17.9 MB (arm64-v8a)**, inside the D-14 40 MB budget with room for the D-47 starter pack. The 51.7 MB figure from a plain `flutter build apk` is the fat multi-ABI artifact and is never what Play delivers; always measure with `--split-per-abi`.
- **QualityGate at 1280x720: 5.27 ms per frame** against the D-16 budget of 30 ms. The budget holds with roughly 6x headroom even in debug, so the stride/frame-skip design is not merely justified but generous.
- **ImageProcessor.prepare on a 2048x1536 photo: 1572 ms**, 2592 KB in, 658 KB out (synthetic noise, worst case for JPEG). This settles D-12's isolate requirement as fact: on the UI thread it would freeze the app for over a second.

## Technical debt

- Device registration accepts any well-formed Ed25519 public key with no proof of possession: a client is not yet challenged to sign anything. Device tokens only ever unlock that device's own guest data, so the exposure is small, but the real gate is App Check attestation (D-29), which is not built. Do not add account-scoped data to device tokens before that lands.
- `AppServices.open()` has no guard against a second connection to the same database file, and `main()` never disposes it. Harmless while `main` runs once per process, but a future in-place restart, a data-wipe flow, or a background isolate touching the database would hit `SqliteException(5): database is locked` (observed on device). Closing a live connection while screens hold streams also raises `ConnectionClosedException`, so any such flow must unmount first.
- `main()` has no failure path: if `AppServices.open()` throws (locked file, corrupt database, no storage), the app dies before `runApp` and the farmer sees a black screen. Needs an honest startup-failure surface before release.
- `cupertino_icons` is declared but unused; the release build warns about its missing font assets. Drop it at the next dependency train (D-41 budget).
- Inference decision constants (per-class thresholds, temperature, rejectionFloor default, minMargin 0.1) are **provisional**: real values come from a fitted calibration set per model version, and the minMargin near-tie rule in particular needs ML + Agri validation (it is a safety net beyond what D-17 specified). Owner: ML + Agri.
- QualityGate thresholds (minEdgeEnergy 8, luminance 40..220) and the D-16 30ms-per-frame budget are **provisional and unvalidated on hardware**. They need reference-device-lab calibration against real field photos before launch; too strict refuses genuine diseased leaves, too loose defeats the gate. Owner: Perf + Agri.
- History tiles render the raw model label; KB display names replace this when advisory content lands (D-35).
- **No font is bundled**, so Devanagari glyph extents come from the OEM ROM and the `KdType` line heights cannot be made deterministic. A Noto Sans Devanagari subset is roughly 180 to 260 KB against a 40 MB budget. Needs an asset added to the repo, so it is a decision for the owner rather than something a module can quietly do.
- **Four P0s from the Module 12 review remain open by sequencing, not by oversight**: one certainty band (P0-5, `topProbability` is still computed and never read), the confident card having no action or correction path (P0-6, still pinned by a test), out-of-scope copy blaming the photo when the cause is coverage (P0-7), and the isolate spawn landing inside the shutter flash (P0-8). The first three are content-shaped and belong with the advisory module; the fourth is Module 15.
- Home still has no bottom navigation and the comfortable lower half of the screen is empty, which the reach analysis flagged. Deferred deliberately: it should land with the handbook that gives it destinations worth navigating to.
- `KdElevation` and `KdMotion` are defined but not yet consumed; motion lands in Module 15. Defining them first is the point (a duration invented at a call site is how a design system drifts), but they are unused surface until then.

## Lessons encoded in code (do not regress)

- **A rejection floor at or below chance level is a dead rule.** The top softmax probability over N classes is never below 1/N, so an open-set rejection threshold under 1/N can never fire: it looks like protection while silently labelling photos of walls as diseases. ModelPack refuses such a pack, and an omitted floor defaults to `min(1.5/N, 0.75)`. Packs also need at least two labels.
- **Blur metric is mean absolute Laplacian, not variance.** The textbook variance recipe assumes full-pixel sampling. Once frames are subsampled for the frame budget, a regular texture (woven mat, mesh screen) can alias so every sampled Laplacian shares a sign, collapsing variance to zero and refusing a perfectly sharp frame. A regression test in packages/capture pins this.
- **Widget tests never drive a live drift database** (Module 5): fake the core_domain ports instead.
- **Stream-driven UI needs two pumps in tests** (Module 7): `pump()` builds the pending frame and only then yields, which is when the stream-delivery microtask runs `setState`. One pump asserts against the previous frame and reads as a product bug when it is test timing. See `_emit` in app/test/capture_test.dart.
- **`find.byType` compares exact runtime types** (Module 7): `FilledButton.icon` builds a private subclass, so `find.byType(FilledButton)` finds nothing. Give such widgets a named Key (e.g. `shutterKey`) and find by key.
- **`ColorScheme.fromSeed` does not return the colour you gave it** (Module 12). Seeding runs the M3 tonal palette generator; #1B5E20 comes back as #3C6939. A token file plus a seeded theme means the audited value never reaches a pixel, and no test notices because nothing compares them. The scheme is now written out explicitly and `contrast_test.dart` asserts `scheme.primary == KdColors.primary`.
- **A contrast figure in a comment is not a measurement** (Module 12). Four of the original token comments were wrong and the headline one was overstated in the flattering direction, which is the same class of decorative claim V1 was criticised for. Ratios live in assertions now, and the calculator is itself checked against the canonical WCAG pairs so a broken calculator cannot silently pass a bad palette.
- **Three colours cannot separate three states** (Module 12). A rail needs 3:1 against white to read as a boundary, which caps its luminance; three colours inside that cap span at most about 3.5:1 end to end, so the middle one cannot clear 3:1 against either neighbour whatever the hues. State is therefore always carried by glyph and words too. This is asserted, not just written down.
- **`childAspectRatio` derives tile height from tile width**, so a grid built that way ignores its content and its text scaler entirely (Module 12). It produced real overflows on 320x640 and 360x800 at the DEFAULT font size and survived four modules because the default flutter_test surface is 800x600, wider and shorter than any target phone. Test surfaces must be set explicitly; `useScreen` in `test/helpers/pump_app.dart` does it.
- **Flutter's `Typography.tall2021` is byte-identical to `englishLike2021`** in Material 3 (Module 12). There is no built-in tall-script theme, so Devanagari renders at Latin line height with Latin letter spacing unless you build the column yourself. Letter spacing in Devanagari breaks the shirorekha; line height under about 1.45 collides stacked matras.
- **`initialLocale` on a mounted widget is ignored** (Module 12): it is read in `initState`, so a test that pumps the same widget type twice keeps the first State and silently compares a value against itself. Key the widget by locale when re-pumping.
- **A corrupted `.dart_tool/pub/workspace_ref.json` (null bytes) crashes the flutter tool** with a JSON FormatException during `pub get` (Module 7, caused by killed background runs). Delete the file and re-run `flutter pub get`.

## APIs created

`/v1` is additive-only from here (D-09, D-27). OpenAPI is served at `/v1/openapi.json`.

- `POST /v1/devices` -> 201 `{device_id, access_token, refresh_token, expires_in}`. Guest-first device registration (D-13). Keyed on the public key, so a reinstall reusing the same hardware-backed key returns the existing device instead of a duplicate. Requires `Idempotency-Key`.
- `POST /v1/auth/refresh` -> 200 `{access_token, refresh_token, expires_in}`. Rotates the refresh token. Reuse of a spent token revokes every token for the device, because a stolen token and a stale one are indistinguishable from the server. All failures return an identical 401 body so a holder cannot learn why. Requires `Idempotency-Key`.
- `GET /healthz` -> 200, excluded from the schema.

Cross-cutting: every mutating `/v1` request requires `Idempotency-Key`; a repeat replays the stored response with `Idempotent-Replay: true`; the same key with a different body is 409 `idempotency_key_reused`; a concurrent duplicate is 409 `request_in_flight`; non-2xx responses are never cached, so a client that fixes its input can retry the same key.
